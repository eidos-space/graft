**先预测，再查询**

本练习验证工作区、暂存区和历史的关系。它执行真实的本地命令，不是教学模拟。

你需要安装 [Graft CLI](/zh/docs/overview/installation/)，并使用 `sqlite3` 查询导出的数据库。在新的临时目录中操作。每次 `graft sql` 都会自行打开和关闭数据库连接；切换或恢复前，关闭其他应用连接。

## 1. 记录一条笔记

```bash
mkdir graft-book-lab
cd graft-book-lab
graft init
graft sql --db app.sqlite \
  "CREATE TABLE notes(id INTEGER PRIMARY KEY, body TEXT NOT NULL);"
graft sql --db app.sqlite \
  "INSERT INTO notes VALUES (1, 'first');"
printf '{"theme":"paper"}\n' > settings.json
graft add app.sqlite
graft add settings.json
graft commit -m "save first note"
graft status
```

**检查：**状态干净。HEAD 记录了一条笔记和设置文件。

## 2. 暂存两条笔记，再写入第三条

提交前先判断：这次提交会包含几条笔记？

```bash
graft sql --db app.sqlite "INSERT INTO notes VALUES (2, 'second');"
graft add app.sqlite
graft sql --db app.sqlite "INSERT INTO notes VALUES (3, 'third');"
graft diff --rows --staged app.sqlite
graft diff --rows
graft commit -m "save two notes"
```

**检查：**暂存差异显示第二条笔记，未暂存差异显示第三条。commit 记录的是暂存的两条笔记快照。

## 3. 比较历史内容与当前内容

导出到工作区外尚未使用的路径：

```bash
graft export --source HEAD --output ../graft-book-head.sqlite app.sqlite
sqlite3 ../graft-book-head.sqlite 'SELECT id, body FROM notes ORDER BY id;'
graft sql --db app.sqlite "SELECT id, body FROM notes ORDER BY id;"
graft status
```

**检查：**导出数据库包含第 1、2 行，工作区包含第 1、2、3 行。status 报告剩余的工作区变化。

如果两次查询都返回三行，检查是否在插入第三条后再次执行了 `add`。

## 4. 记录第三条，再比较提交

```bash
graft add app.sqlite
graft commit -m "save third note"
graft diff --rows HEAD~1 HEAD app.sqlite
graft log
```

**检查：**差异报告新增第 3 行。HEAD 现在记录了三条笔记。

## 5. 修改一个分支，再切换回来

先判断：仅创建分支，会改变当前笔记吗？

```bash
graft branch experiment
graft sql --db app.sqlite "SELECT body FROM notes WHERE id=1;"
graft switch experiment
graft sql --db app.sqlite "UPDATE notes SET body='edited on experiment' WHERE id=1;"
graft add app.sqlite
graft commit -m "edit first note"
graft switch main
graft sql --db app.sqlite "SELECT body FROM notes WHERE id=1;"
graft switch experiment
graft sql --db app.sqlite "SELECT body FROM notes WHERE id=1;"
```

**检查：**创建分支没有改变笔记。在 `main` 上，第 1 行是 `first`；在 `experiment` 上，它是 `edited on experiment`。切换会安装所选版本的数据库。

## 6. 替换未记录的修改

以下删除只针对本练习的临时数据库：

```bash
graft sql --db app.sqlite "DELETE FROM notes WHERE id=3;"
graft status
graft restore --source HEAD -- app.sqlite
graft sql --db app.sqlite "SELECT id, body FROM notes ORDER BY id;"
graft status
```

**检查：**第 3 行重新出现，状态干净。restore 用 HEAD 的内容替换未记录的删除，没有创建新提交。

## 解释观察结果

现在尝试回答：

1. 为什么记录两条笔记后，工作区仍有三条？
2. 为什么创建分支没有改变数据库？
3. 为什么导出可以检查 HEAD，却不改变应用数据？
4. 哪个操作让删除的行重新出现？

答案分别是：commit 使用暂存快照；分支是指针；导出写入独立文件；restore 把 HEAD 的内容写回已跟踪路径。

这些检查验证操作行为。无需读取私有暂存区文件、解释缓存布局或测量存储目录大小。

继续用[合并冲突指南](/zh/docs/guides/merge-conflicts/)练习两个分支的变化，或用[远端同步指南](/zh/docs/guides/sync-remotes/)传输已记录的历史。
