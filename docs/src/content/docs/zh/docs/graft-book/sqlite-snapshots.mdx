**数据库快照包含什么**

**快照（snapshot）** 是一份一致的、已提交的 SQLite 数据库状态。它可以恢复成普通 SQLite 文件。

假设应用插入一条笔记，并提交 SQLite 事务。在 WAL 模式下，这条笔记可能仍在 `app.sqlite-wal` 中，而没有写入主文件 `app.sqlite`。只复制主文件可能漏掉它。

执行 `graft add app.sqlite` 时，Graft 捕获一份私有的一致数据库镜像。捕获包含已提交的 WAL 内容，不包含未提交事务。你无需手动执行 checkpoint。

```text
app.sqlite + app.sqlite-wal 中已提交的内容
                   |
                   | 一致捕获
                   v
             私有数据库镜像
                   |
                   | 存储变化块
                   v
               暂存快照
```

私有镜像是临时文件。暂存不会替换应用正在使用的数据库。

每个数据库的捕获是一致的。但把多个数据库和文件放进一次提交，不会在它们之间建立应用级事务。如果这些路径必须对应同一个检查点，应用需要协调写入。

## 如何复用未变化的内容

Graft 把捕获的镜像划分为 4 KiB 存储块，与暂存或已提交的基准比较，再记录变化块。

下面是简化示例。字母表示字节内容，不表示 SQL 行。

```text
快照 A：[A][B][C][D]
快照 B：[A][B][X][D][E]

B 的新内容：第 3 块 = X，第 5 块 = E
复用的内容：第 1、2、4 块
```

快照 B 仍表示完整数据库。读取时，会组合新块与之前存储记录中的未变化块。恢复时，会据此重建文件。

可以把它想象成一本活页书：后续版本保留没变的页，替换变化的页。第一次捕获需要所有块；后续捕获可以复用未变化的内容。快照描述的是完整状态，不是一份只装着变化内容的独立文件。

在上面的例子中，读取 B 会选择：

| 位置 | B 使用的内容 |
| --- | --- |
| 1、2、4 | 之前存储中未变化的 A、B、D |
| 3 | 替换内容 X |
| 5 | 新增内容 E |

选择 B 不会改变 A。已保存内容是不可变的，每个快照选择属于自己的内容和逻辑大小。恢复 B 会重建完整 SQLite 文件，应用再打开这个普通文件。它不需要重放产生 B 的 SQL。

修改一行可能影响多个块，因为 SQLite 还要维护索引和元数据。存储目录大小包含额外开销，不能用来计算行变化数量。

## 两种“页”

SQLite 有自己的物理页大小。Graft 存储块固定为 4096 字节。一个 8 KiB 的 SQLite 页占用两个 Graft 块。

块边界用于决定存储复用，不决定行身份或合并结果。逻辑差异与合并会另行解释 SQLite 表和结构。

## 从存储块到能理解的变化

假设两个捕获版本中都有一张 `projects` 表：

| 记录 | 快照 A | 快照 B |
| --- | --- | --- |
| `id = 1` | `budget = 100` | `budget = 120` |
| `id = 2` | 不存在 | `budget = 200` |

物理比较识别变化的存储内容。行比较识别一次修改和一次新增。它们回答不同的问题：一页可以容纳多行，一行变化也可能影响多页。

```bash
graft diff HEAD~1 HEAD app.sqlite
graft diff --rows HEAD~1 HEAD app.sqlite
```

第一条命令识别变化路径，第二条还会解释受支持的数据库变化。行分析按身份对齐记录：普通 rowid 表使用 `rowid`，`WITHOUT ROWID` 表使用声明的主键。例子中的 `id` 如果声明为 `INTEGER PRIMARY KEY`，就是 rowid 的别名。

适用时，结果还会包含表结构变化、不透明变化和限制。行级 diff 为空，不代表全部数据库内容都未变化。见[行与文件差异](/zh/docs/guides/diff-rows-and-files/)。

## 先捕获，再记录历史

`graft add app.sqlite` 捕获并暂存数据库版本。`graft commit` 记录这个暂存版本，不会再次捕获实时数据库。暂存后的写入，要等下一次 `add` 才能进入提交。

存储块回答“如何重建这个版本”，仓库提交回答“这是哪个应用检查点”，SQLite diff 回答“改了什么”。在应用中展示历史时，应当区分这三个角色。

## 需要调试存储时，再理解坐标

存储提交记录变化块和结果的块数量。它的坐标是 `(LogId, LSN)`：日志标识，以及该日志内的序号。

LSN 只在同一日志内有序。两个日志中的 LSN 3 不表示同一版本，也不能用来比较时间先后。

快照描述符记录卷、逻辑大小、有序日志范围，以及预期的存储提交哈希。日志范围说明如何找到每个块。卷是存储沿袭的句柄；不可变的描述符标识历史引用的数据库状态。

应用历史使用仓库提交、分支和标签。存储坐标用于调试存储。

## 没有变化会怎样

如果块内容和逻辑大小与基准相同，Graft 可以复用快照，无需追加存储提交。

数据库缩小时，旧块可能仍保存在存储中，但已超出新快照的逻辑大小。缩短文件不等于安全擦除。清理不可达存储数据是另一个垃圾回收过程。

当前捕获实现使用 SQLite 在线备份，并在适合的 macOS 回滚日志数据库上使用受保护的文件克隆优化。两条路径都必须捕获一致的已提交状态。

继续阅读[暂存与提交](/zh/docs/graft-book/stage-and-commit/)。精确的快照身份与日志范围规则见[存储规范](/zh/docs/specifications/)。
