**应用版本存在哪里**

工作区包含应用打开的文件。Graft 在旁边的 `.graft/` 中保存仓库状态。

```text
project/
├── app.sqlite
├── settings.json
├── attachments/
│   └── report.pdf
└── .graft/          Graft 历史、暂存、存储与恢复状态
```

这是物理目录树。`app.sqlite` 是一个文件，表是这个文件内部的逻辑内容。

使用仓库命令查看或修改历史。应用不应把直接编辑 `.graft/` 中的文件当作集成 API。

## 一次提交记录一个完整版本

假设 C1 记录了一条笔记和浅色主题，C2 记录了两条笔记和深色主题。

下面表示逻辑引用，不是目录。C1、C2 是教学代号，实际提交 ID 是由内容计算出的哈希。

```text
main -- 指向 --> C2 -- 父提交 --> C1
                  |
                  +-- 树：这个版本的路径清单
                       |
                       +-- app.sqlite：数据库快照
                       +-- settings.json：已记录的文件内容
                       +-- attachments/report.pdf：外部载荷指针
```

**树（tree）** 把路径映射到已记录的内容。**blob 对象** 描述一个路径的内容。提交引用树和父提交。已有对象不可变，新的内容会产生新的对象。

小文本可以直接保存在 blob 中。二进制文件、大文本和配置为外部存储的文件使用**外部载荷（external payload）**：文件字节单独存储，用内容哈希标识。指针已经存在时，文件字节可能还没有下载到本地。

## 分支指向一次提交

**引用（ref）** 是可变的指针。`main` 这样的分支就是一种引用，会在提交后移动。

```text
提交前：main -> C1
提交后：main -> C2 -> C1
```

在 C2 创建另一个分支不会复制数据库，只会增加一个指向同一版本的指针。

**HEAD** 表示当前位置。通常它指向当前分支；游离 HEAD 直接指向提交。首次提交前，HEAD 可以指向 `main`，但这个分支还没有提交。

用以下命令查看这些关系：

```bash
graft log
graft show HEAD
graft branch
```

## 暂存区选择当前版本上的变化

没有进行合并时，暂存区保存相对 HEAD 的变化。暂存一个路径，就为下次提交替换或删除这个路径。没有暂存记录的路径沿用 HEAD 中的版本。

合并时，暂存区还可以保存冲突路径的三个版本：

| 阶段 | 含义 |
| --- | --- |
| 1 | Base：共同祖先 |
| 2 | Ours：本地版本 |
| 3 | Theirs：传入版本 |
| 0 | 为下一次提交选定的结果 |

未解决的冲突会阻止完成合并。某一侧缺失，可能表示该路径被删除。

## 根据问题检查状态

| 问题 | 检查方法 |
| --- | --- |
| 应用现在读到什么？ | 工作区文件或 SQL 查询 |
| 已暂存什么？ | `graft status` 和 `graft diff --staged` |
| 记录过什么？ | `graft show HEAD`、历史差异或导出 |
| 当前在哪个分支？ | `graft branch` |
| 还有什么冲突？ | `graft conflicts` |

内部缓存帮助 Graft 提高效率，不定义历史版本。引用、对象、暂存状态和合并恢复记录各有职责，不能把整个 `.graft/` 当作可丢弃的缓存。

对象编码、路径规范化和引用更新规则见[仓库规范](/zh/docs/specifications/)。
