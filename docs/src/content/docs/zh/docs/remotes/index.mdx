Graft 远端把仓库对象、引用、SQLite 快照数据和外部载荷保存在本地 `.graft/`
目录之外。它支持 fetch、pull、push 和 clone，但不会替代 SQLite 事务，也不是
实时操作日志。

## 选择后端

| 后端 | 适用情况 |
| --- | --- |
| `memory` | 单元测试和短生命周期 fixture。 |
| `fs://` | 本地开发、挂载存储和端到端冒烟测试。 |
| `s3://` 或 `s3_compatible://` | 由应用环境直接管理的对象存储。 |
| `https://` | 需要身份验证、授权、限额与租户路由的产品同步。 |

准确语法与凭据规则见[远端 URI](/zh/docs/reference/remote-uris/)。

## 构建 HTTP 远端

Graft 把协议行为、框架和存储职责分开：

| 软件包 | 职责 |
| --- | --- |
| `@eidos.space/graft-remote` | 基于 Fetch 的协议引擎、校验与后端接口。 |
| `@eidos.space/graft-remote-hono` | Hono 路由适配器。 |
| `@eidos.space/graft-remote-cloudflare` | R2 与 SQLite Durable Object 后端辅助实现。 |

宿主服务仍然负责身份验证、授权、仓库命名、请求限制、密钥、路由与部署。

## 安全边界

远端凭据必须作为显式的客户端或适配器输入。不要把 bearer token 写入仓库配置、
远端 URL、日志、缓存或结果 payload。生产环境 HTTP 远端应使用 HTTPS，并对每个
discovery、read 和 write 操作执行仓库级访问控制。
