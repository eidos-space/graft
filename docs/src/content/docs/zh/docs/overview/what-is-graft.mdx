---
title: 什么是 Graft？
description: 理解 Graft 记录什么，以及应用保存、版本记录和远端同步的区别。
---

Graft 为 SQLite 数据库及相关应用文件记录版本。你可以比较版本、恢复已记录状态、创建分支、合并受支持的变化，并把历史传到远端。

应用继续使用普通 SQLite 连接和文件 API。

## 从一个应用目录开始

```text
app-data/
├── app.sqlite
├── settings.json
└── attachments/
    └── report.pdf
```

`app.sqlite` 中的笔记可能引用 `attachments/report.pdf`。如果只恢复数据库，被引用的文件可能缺失，或内容已不同。

Graft 可以把选定的数据库与文件版本记录在同一次提交中。一起恢复或切换相关路径，就能回到已记录的组合。应用仍需要协调写入，并决定哪些路径应该一起记录。

## 保存、记录与同步是三个动作

| 你想做什么 | 动作 | 结果 |
| --- | --- | --- |
| 在应用中保存笔记 | 提交 SQLite 事务 | 当前数据库变化 |
| 选定检查点 | `graft add` | 暂存一致的数据库快照与选定文件字节 |
| 记录检查点 | `graft commit` | 暂存内容进入仓库历史 |
| 把历史传到别处 | `graft push` | 远端收到已记录版本与所需内容 |
| 在本地使用历史内容 | 恢复或切换 | 可能替换已跟踪的工作区文件 |

应用每次保存笔记，不会自动执行 commit 或 push。

## Graft 如何理解 SQLite

文件级比较可以告诉你数据库字节发生变化。Graft 还能把受支持的变化解释为表结构、表和行变化。

- **捕获：**生成一致快照，包含已提交的 WAL 内容。
- **存储：**在数据库版本之间复用未变化的 4 KiB 块。
- **差异：**显示受支持的行和表结构变化。
- **合并：**组合兼容变化；无法安全自动完成时，报告冲突。

不受支持或不透明的 SQLite 内容仍是明确限制。行差异为空，不代表整个数据库没变。

Graft 提供类似 Git 的工作流，使用自己的仓库与远端格式。历史保存在应用文件旁的 `.graft/` 中。

## 是否适合你的应用

如果用户需要检查点、变化审查、旧版本、分支工作流，或本地应用数据的可选历史同步，可以考虑 Graft。

事务写入仍由 SQLite 负责。身份验证与授权仍由应用或服务负责。备份与保留策略需要单独规划。Graft 基于提交的同步不是实时操作日志复制。

Graft 仍是实验性项目。发布与稳定性边界见[项目状态](/zh/docs/overview/status/)。
