Graft 为普通 SQLite 数据库和应用文件提供版本管理。

```text
SQLite 负责事务，Graft 负责历史。
```

## 它解决的问题

应用的持久状态通常分布在多个路径中：

```text
app-data/
  data.sqlite
  settings.json
  attachments/
    invoice.pdf
```

`data.sqlite` 中的一行可能引用 `attachments/invoice.pdf`。如果恢复、建立分支
或同步时只处理其中一个路径，应用可能得到无法使用的状态。

Graft 把选定的数据库与文件记录在同一个仓库提交中。这个提交表示一份完整、
一致的应用状态。

## Graft 提供什么

- 一致捕获 SQLite 快照，包括已提交的 WAL frames；
- repository index 与不可变提交；
- 路径级差异和受支持的 SQLite 行级差异；
- 分支、恢复、三方合并与结构化冲突；
- 本地、对象存储与 HTTP 远端；
- 结构化 CLI 输出和进程内 Node.js SDK。

工作区中仍然是普通 SQLite 文件。现有 SQLite library 不需要自定义 VFS 或
Graft 专用查询接口。

## 它位于哪一层

当应用需要为一组相关数据库和文件提供可见历史、检查点、变更审查、分支式工作流、
恢复或同步时，使用 Graft。

Graft 不会替代：

- SQLite 事务；
- 应用的身份验证与授权；
- 实时 operation-log replication；
- 通用源码仓库；
- 独立的备份与保留策略。

## 开发者接入面

| 接入面 | 用途 |
| --- | --- |
| Graft CLI | 评估、脚本、自动化和 JSON 子进程接入。 |
| Node.js SDK | 进程内常驻仓库会话。 |
| 远端软件包 | 通过你运营的基础设施提供带身份验证的 HTTP 同步。 |
