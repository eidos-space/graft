title: 行与文件差异
description: 先选择要比较的两个状态，再解释路径、行、表结构与不受支持的变化。
---

差异检查回答两个问题：**比较哪两个状态**，以及**解释多少内容**。

先选择状态：

| 问题 | 命令 | 比较方向 |
| --- | --- | --- |
| 暂存之后又改了什么？ | `graft diff` | 暂存区到工作区 |
| 将要提交什么？ | `graft diff --staged` | HEAD 到暂存区 |
| 两个版本之间改了什么？ | `graft diff HEAD~1 HEAD` | 第一个父提交到当前提交 |
| 两个分支有什么区别？ | `graft diff main experiment` | main 到 experiment |

方向很重要。插入和删除描述从第一个状态变成第二个状态所需的变化。这些命令不改变引用、暂存区、合并记录或已跟踪文件。

## 1. 定位变化路径

```bash
graft diff HEAD~1 HEAD
graft diff --json HEAD~1 HEAD
```

路径输出标识新增、删除和修改，还报告 `kind`（数据库、文本或二进制）与 `storage`（快照、内联或外部存储）。

选择一个已记录的数据库：

```bash
graft diff HEAD~1 HEAD app.sqlite
```

选择一种内容类型：

```bash
graft diff --kind sqlite_database
graft diff --kind text_file
graft diff --kind binary_file
```

## 2. 展开数据库变化

添加 `--rows`：

```bash
graft diff --rows HEAD~1 HEAD app.sqlite
graft diff --json --rows HEAD~1 HEAD app.sqlite
graft diff --rows --staged app.sqlite
```

如果第二个版本新增第 2 条笔记，预期看到插入行。如果修改第 1 条，预期看到包含旧值与新值的更新。

数据库结果可以包含表结构变化、行变化、不透明变化、能力和限制。行列表为空，不能证明整个数据库没变。

## 3. 结合详细内容解读逻辑状态

| `logical_status` | 含义 | 审查方式 |
| --- | --- | --- |
| `logical_changes` | 找到了受支持的行或表结构变化 | 显示变化及附带限制 |
| `unsupported_logical_surface` | 无法完整解释变化的 SQLite 内容 | 显示限制，保留文件级审查 |
| `file_changed_no_supported_logical_changes` | 字节变化，但受支持的逻辑内容没有净变化 | 描述文件变化，不虚构行修改 |
| `row_diff_unavailable` | 该文件无法进行行分析 | 使用路径级信息 |

**检查：**一起阅读行、表结构与不透明变化。二进制附件应使用路径元数据和合适的文件查看器。

## 比较两个独立 SQLite 文件

手上是数据库文件，而不是仓库版本时，使用 `--no-index`：

```bash
graft diff --no-index old.sqlite new.sqlite
graft diff --no-index --rows old.sqlite new.sqlite
graft diff --no-index --rows --json old.sqlite new.sqlite
```

它只接受两个普通 SQLite 文件，不要求仓库。两边都进行一致捕获，包含已提交的 WAL 内容。

默认比较物理快照。`--rows` 展开逻辑表结构、表、行与不透明变化。`--staged`、`--root`、`--kind` 和 `--content` 等仓库选择参数不适用。

## 在应用中使用正确边界

集成时使用 `--json`。用路径摘要导航，为选定数据库显示逻辑细节。保留能力与限制字段，不要把所有空行列表显示为“没有变化”。

用户可见的历史使用仓库提交 ID、分支和标签。存储 LSN 属于特定日志，不是全局应用版本。

[动手练习](/zh/docs/graft-book/hands-on-lab/)会分别观察已暂存的插入与后续未暂存的插入。
