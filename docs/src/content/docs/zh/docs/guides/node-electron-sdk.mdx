`@eidos.space/graft` 是 Graft 面向 Node.js 与 Electron 的进程内 SDK。它在多次调用之间
保留 repository runtime，复用 CLI 同一套 Rust repository 实现和官方 Remote，并通过
ABI-stable Node-API 8 native class 暴露。

它与 Git 生态的设计类比是 `libgit2 → Graft Rust session core`、
`NodeGit → ABI-stable Node-API addon`。这只是帮助理解生命周期的类比，不是依赖；SDK
不会复制 Git/Graft 协议，也不是 daemon 或 JSON-stdin CLI wrapper。

## 安装与打开

```sh
pnpm add @eidos.space/graft
```

```js
const { RepositorySession } = require("@eidos.space/graft")

const session = await RepositorySession.open(spaceRoot)
try {
  await session.init()
  const status = await session.status()
  const changes = await session.diff({ rows: true })
} finally {
  await session.close()
}
```

每个 canonical repository path 保留一个 session。同一 session 的调用完整串行；不同
repository 的 session 可以并行。native 工作在 libuv worker thread 上运行，不阻塞
JavaScript 主线程。

## Electron 进程边界

SDK 应由 Electron utility process 直接加载，不进入 renderer。repository path、credential
和 native class 留在 typed IPC 后面，并由 utility process 生命周期持有 session map。

Electron 打包需要把 `*.node` 放在 ASAR 外。npm 根包会按当前主机选择精确版本的 optional
binary package；首版覆盖 macOS arm64/x64、Linux glibc arm64/x64 和 Windows x64，不在
安装阶段编译或下载二进制。

## Worktree materialization

| 操作 | 会替换、新建或删除 tracked worktree 文件 |
| --- | --- |
| `init`、`status`、`statusIncremental`、`addAll`、`stagePaths`、`untrackPaths`、`commit` | 否 |
| `diff`、`diffPaths`、`history`、`historySummaries`、`commitDetails`、`commitChangedPaths`、`isIgnoredPaths`、`inventory` | 否 |
| `configureRemote`、`push`、`fetch` | 否 |
| `restore`、`restorePaths`、`pull`、`cloneRepository` | **是** |

materializing 操作前先阻止新的应用写入、排空 transaction，并关闭受影响的 SQLite
handle；SDK promise 结束后重新打开并验证。Graft repository session 本身可以继续常驻。
应用 gate 可调用 `operationMaterializesWorktree(name)` 读取这份契约。

<Aside type="caution" title="一个 repository writer">
  同一 repository 的第二个 SDK session 或外部 Graft writer 会收到
  `GRAFT_SDK_REPOSITORY_BUSY`。不要高频重试，应关闭旧 owner 或提示用户停止外部 writer。
</Aside>

## Credential

HTTP bearer token 必须显式注入并只保存在内存：

```js
await session.configureRemote({
  name: "origin",
  url: "https://sync.example.com/org/space",
  bearerToken,
})

session.setHttpBearerToken("origin", rotatedToken)
session.clearHttpBearerToken("origin")
```

SDK 不读取 `GRAFT_REMOTE_TOKEN`，不把 token 写入 repository config 或 URL，并从错误中
脱敏。CLI 仍保留环境变量兼容路径，但应用不应把它作为 SDK credential transport。

## Close、reopen、crash 与取消

`close()` 会拒绝排队中的工作，等待当前命令完成，释放 runtime，并且可以重复调用。
`reopen()` 从持久状态重新构建 runtime。utility process 崩溃后由操作系统释放 storage lock；
替代进程直接打开新 session，不需要 daemon lease 或 PID 文件。

异步方法接受 `AbortSignal`。队列中和尚在执行的长循环都会协作检查取消信号；取消后
同一 session 仍可继续使用。批量 mutation 可能完成前缀，重试前应重新读取 status。

调用方应按 `error.code` 分支，例如 `GRAFT_SDK_SESSION_CLOSED`、
`GRAFT_SDK_SESSION_CLOSING`、`GRAFT_SDK_REPOSITORY_BUSY` 与
`GRAFT_SDK_REPOSITORY_COMMAND`。

历史列表应使用不读取 tree/blob 的 `historySummaries`。展开 checkpoint 时，再调用最多
100 条一页的 `commitChangedPaths`；普通 commit 用返回的 `parent` 和 `revision` 作为
`diffPaths` 的 `from`/`to`，root commit 使用 `root: revision`。显式路径 diff 只读取匹配的
tree/index entry 与对应 blob；telemetry 中的 `path_filter_fast_path: true` 与
`full_tree_paths_hydrated: 0` 表示没有加载完整 commit map。

status metadata/generation cache 绑定常驻 `RepositorySession`。新开 session 仍需执行一次
完整分类和 fingerprint，因此 Space 生命周期内应复用同一个 session；本候选版本尚不包含
跨 session/进程持久化的冷启动分类缓存。

`stagePaths` 会把 canonical SQLite snapshot 写入 index，`commit` 只从该 index state 推进
历史；两者都不会替换工作区数据库。因此自动 checkpoint 前后可保持应用 SQLite handle
打开，并保留相同的文件 identity。

后来添加 ignore 不会自动取消已追踪文件。先用 `inventory({ kind: "tracked_ignored" })`
诊断并审核，再调用 `untrackPaths({ paths, expectedHead })`。该操作只移除 index entry，
拒绝目录，不会删除或替换工作区文件；被 ignore 的文件也不会被后续 `addAll` 重新加入。
参数和返回类型见 package [README](https://github.com/eidos-space/graft) 和 TypeScript declaration。

Explorer 应通过 `isIgnoredPaths` 一次查询最多 1,000 个 entry，不要逐项跨 utility process
调用。目录结果包含 `has_tracked_descendants`；ignored 目录仍有 tracked descendant 时不可
剪枝。常驻 session 会缓存 index、嵌套 ignore matcher 与 `tracked_ignored` inventory，并在
ignore 文件或 SDK index 变化后失效。
