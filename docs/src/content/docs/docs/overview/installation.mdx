The fastest way to try Graft is the CLI. Applications can later load the
SQLite extension, or use the resident Node.js/Electron SDK.

## Install The CLI

Install the version documented by this site:

```bash
curl -fsSL https://raw.githubusercontent.com/eidos-space/graft/main/install.sh \
  | GRAFT_VERSION=0.9.0 sh
```

Then check the binary:

```bash
graft --version
# graft 0.9.0
```

<Aside type="note" title="Latest release">
  Omit `GRAFT_VERSION=0.9.0` to install the latest published release. Its
  behavior may be newer than this v0.9.0 documentation.
</Aside>

Prebuilt archives are also available from the
[GitHub releases page](https://github.com/eidos-space/graft/releases).

## Build The CLI From Source

From the repository root:

```bash
cargo build -p graft-tool --bin graft --release
```

The binary is written to:

```text
target/release/graft
```

Add it to your shell path:

```bash
mkdir -p ~/.local/bin
ln -sf "$(pwd)/target/release/graft" ~/.local/bin/graft
hash -r
graft --help
```

## Build The SQLite Extension

Build the dynamic SQLite extension:

```bash
cargo build -p graft-ext --release
```

The exact library filename depends on the platform. It is written under
`target/release/` and can be loaded by SQLite:

```sql
.load ./libgraft_ext
```

Use the extension when your app deliberately wants the Graft VFS as a live
page-storage data plane. Repository commands are not exposed as SQLite
PRAGMAs; use the CLI and its JSON output for the control plane.

## Build The Docs

The documentation site lives in `docs/`:

```bash
cd docs
pnpm install
pnpm build
```

## Install The Node.js And Electron SDK

```bash
pnpm add @eidos.space/graft
```

The npm package provides long-lived in-process repository sessions and prebuilt Node-API 8
binaries. Continue with the [Node.js and Electron SDK guide](/docs/guides/node-electron-sdk/).
