---
title: What Is Graft?
description: Understand what Graft records and how application saves, versions, and remote sync differ.
---

Graft records versions of SQLite databases and related application files. You can compare versions, restore a recorded state, branch, merge supported changes, and transfer history to a remote.

Your application keeps using ordinary SQLite connections and file APIs.

## Start with one application directory

```text
app-data/
├── app.sqlite
├── settings.json
└── attachments/
    └── report.pdf
```

A note in `app.sqlite` may refer to `attachments/report.pdf`. If you restore only the database, the referenced file may be missing or have different contents.

Graft can record selected database and file versions in one commit. Restoring or switching the relevant paths together lets you return to their recorded combination. The application still has to coordinate writes and decide which paths belong together.

## Saving, recording, and syncing are separate

| You want to… | Action | Result |
| --- | --- | --- |
| Save a note in the application | Commit a SQLite transaction | The current database changes |
| Select a checkpoint | `graft add` | A consistent database snapshot and selected file bytes are staged |
| Record that checkpoint | `graft commit` | The staged content becomes repository history |
| Send recorded history elsewhere | `graft push` | The remote receives the recorded version and required content |
| Use recorded content locally | Restore or switch | Tracked worktree files can be replaced |

There is no automatic commit or push each time the application saves a note.

## What makes it SQLite-aware?

A file-level comparison can tell you that a database's bytes changed. Graft can also interpret supported changes as schema, table, and row changes.

- **Capture:** include committed WAL content in a consistent snapshot.
- **Storage:** reuse unchanged 4 KiB chunks across database versions.
- **Diff:** show supported row and schema changes.
- **Merge:** combine compatible changes and report conflicts where a safe automatic result is unavailable.

Unsupported or opaque SQLite content remains a visible limitation. An empty row diff does not prove that the whole database is unchanged.

Graft offers a Git-like workflow with its own repository and remote formats. Its history lives in `.graft/` beside the application files.

## Is it suitable for your application?

Use Graft when users need checkpoints, change review, earlier versions, branch workflows, or optional history synchronization for local application data.

Keep SQLite transactions for transactional writes. Keep application authentication and authorization in the application or service. Plan backups and retention separately. Graft's commit-based synchronization is not real-time operation-log replication.

Graft is experimental. Read [project status](/docs/overview/status/) for release and stability boundaries.
