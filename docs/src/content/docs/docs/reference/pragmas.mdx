The SQLite extension is a data-plane integration. Its production PRAGMA surface
controls or inspects the Graft Volume behind the currently open `vfs=graft`
database.

Repository operations are intentionally not available through SQLite. Use the
CLI for status, staging, commits, branches, merge, remotes, and JSON output:

```bash
graft status --json
graft add data.sqlite
graft commit -m "save checkpoint"
graft diff --json --rows HEAD~1 HEAD data.sqlite
```

Calling a removed repository PRAGMA, such as `PRAGMA graft_status`, returns an
error directing the caller to the Graft CLI.

## Version

```sql
PRAGMA graft_version;
```

Returns the extension version and build revision when available.

## Volume Inspection

These commands inspect the Volume bound to the current VFS database:

```sql
PRAGMA graft_debug_volume_info;
PRAGMA graft_debug_volume_json_info;
PRAGMA graft_debug_volume_status;
PRAGMA graft_debug_volume_list;
PRAGMA graft_debug_volume_json_list;
PRAGMA graft_debug_volume_tags;
PRAGMA graft_debug_volume_snapshot;
PRAGMA graft_debug_volume_dump_header;
PRAGMA graft_debug_log_lsn;
PRAGMA graft_debug_volume_table_log = 'users';
PRAGMA graft_debug_volume_json_table_log = 'users';
```

## Volume Selection And History

These low-level controls create, select, fork, or move the open Volume:

```sql
PRAGMA graft_debug_volume_new;
PRAGMA graft_debug_volume_switch = '<volume>[:<local-log>[:<remote-log>]]';
PRAGMA graft_debug_volume_clone = '<remote-log>';
PRAGMA graft_debug_volume_fork;
PRAGMA graft_debug_volume_checkout_lsn = '12';
PRAGMA graft_debug_volume_reset_to = '12';
PRAGMA graft_debug_volume_set_message = 'storage commit message';
```

These operate on storage history, not repository commits or branches.

## Storage Sync And Audit

```sql
PRAGMA graft_debug_volume_fetch;
PRAGMA graft_debug_volume_pull;
PRAGMA graft_debug_volume_push;
PRAGMA graft_debug_volume_audit;
PRAGMA graft_debug_volume_json_audit;
PRAGMA graft_debug_volume_hydrate;
PRAGMA graft_debug_volume_export = '/tmp/snapshot.sqlite';
```

`graft_debug_volume_import` remains only as a deprecated error that points to
SQLite `VACUUM INTO`; it is not a supported import workflow.

## Storage Diffs

```sql
PRAGMA graft_debug_show_lsn = '<log-ref>';
PRAGMA graft_debug_diff_lsn = '<from-log-ref>,<to-log-ref>';
PRAGMA graft_debug_volume_dump_commit = '<log-ref>';
PRAGMA graft_debug_volume_diff = '2,4';
PRAGMA graft_debug_volume_diff = '2,4,rows';
PRAGMA graft_debug_volume_json_diff = '2,4,rows';
```

<Aside type="caution">
  `graft_debug_*` commands expose Volume ids, logs, LSNs, pages, and storage
  commits. They are intended for VFS development and diagnostics and are not a
  stable application control API. Product integrations should use repository
  revisions and CLI JSON output.
</Aside>

## Repository Command Replacements

| Removed SQLite surface | Use instead |
| --- | --- |
| `PRAGMA graft_status` | `graft status` or `graft status --json` |
| `PRAGMA graft_add` | `graft add <path>` or `graft add --all` |
| `PRAGMA graft_commit` | `graft commit -m <message>` |
| `PRAGMA graft_diff` | `graft diff`, optionally with `--rows` and `--json` |
| branch, merge, conflict PRAGMAs | `graft branch`, `switch`, `merge`, `conflicts`, `resolve` |
| remote and sync PRAGMAs | `graft remote`, `fetch`, `pull`, `push` |

This separation keeps SQLite responsible for database transactions and Graft's
repository service responsible for version-control operations.
